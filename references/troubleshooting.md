# 常见问题

按流程顺序排列，都是实际遇到过的。

## 锚定（anchor.py）

**段落锚定失败**
- 段落以公式开头：脚本会用公式前后的文字拼模式，仍失败时手工指定。
- 正式版与 arXiv 版措辞不同：换成与 HTML 同源的 arXiv 版 PDF，或手工指定。
- 手工指定：在 `<name>_lines.json` 里按页码找到这一段第一行，记下 `y0`；`band` 是 `<name>_layout.json` 里该页包含这个 y 的带的序号；`col` 是 `L`、`R`，跨栏带写 `F`。写进 `<name>_anchor_override.json`：`{"B4": {"page": 0, "band": 1, "col": "L", "y": 538.8}}`，页码从 0 数。

**图表题锚定失败**：脚本先按图表题正文匹配，失败再按“Table 4”“Fig. 3”“TABLE II”这样的编号标签匹配。几张子表共用一个块、主标题为空时，用第一个子标题定位。仍失败就手工指定。

**附录块被报告为“不在这份 PDF 中”**：HTML 带附录、PDF 没有（会议正式版常见），属正常，这些块不用翻译也不会排版。反过来，如果 PDF 里明明有附录却被这样报告，多半是附录第一个标题没匹配上（比如 HTML 写“Appendix A Xxx”、PDF 写“A. Xxx”，脚本已处理这种写法）；用 `<name>_anchor_override.json` 手工指定那个标题的位置后重跑。

**附录与参考文献排在同一页**：脚本以附录第一个锚点为参考文献的终点。附录另起一页时最可靠；如果附录紧接在参考文献后面、同一页同一栏开始，参考文献最后一段可能和附录开头混在一起，需要渲染出来检查。

**顺序倒挂**：图表题排在正文前面一般是浮动体造成的，属正常；如果两个相邻段落倒挂，多半是匹配到了别处的同一句话，手工指定后一段。

**IEEE 论文的小标题和正文在同一行**：如“1) Master Tool Manipulator: As seen in Fig. 5, …”“Abstract— Robotic …”。标题按行首匹配，正文在行首 40 个字符以内匹配，两者锚在同一行、并为一组；“III-F1”这类编号匹配前会去掉。

**并排的表格和公式被判成一条跨栏带**：例如左栏顶部是表格、右栏顶部是公式，两者之间的空隙太窄，中缝被认为有内容。症状是右栏的段落被锚到 `col: F`。把 `<name>_layout.json` 里这一页的 `bands` 改成一个 `full: false` 的双栏带，再重跑 `anchor.py`。

**带连字的段落锚定失败**：PDF 里的“ﬁ”“ﬃ”是一个字符，HTML 里是两三个字母。`anchor.py` 匹配前已做 NFKC 规范化把连字拆开。

**上一段末尾的“[1, 2].”被当成下一段的开头**：匹配时引用编号会被去掉，只有引用编号的一行就成了空行，再拼上后两行恰好是下一段的开头。脚本已规定这种行不能当段首；锚点仍然偏到上一行时手工指定。

**目录页（附录前的 Contents）把附录标题锚错**：目录里的条目和附录小节标题文字相同，匹配会落到目录上。用 `<name>_anchor_override.json` 把这些标题指到正文里的位置。

## 版面分析（layout.swift）

**一整页被判成一个跨栏带**：页边的竖排水印（arXiv 编号）会被当成横跨中缝的内容。脚本只扫描页宽 6.5%–93.5% 的区域来避开它；如果某篇论文的水印更靠里，调整 `layout.swift` 里的 `0.065` 和 `0.935`。

**首页左边缘夹进 arXiv 竖排编号的碎片**：首页的编号离正文较近时会被算进栏的左边界。`render.py` 发现某页左右边界比全文中位数宽出 8 pt 以上，会改用中位数。

**页码被当成一个跨栏带**：高度小于 20 pt 且没有挂任何块的带会被自动跳过。

**单栏论文被判成双栏（或反过来）**：判定依据是“有墨迹的行里，中缝也有墨迹的比例超过 0.45 的页数是否过半”，输出的第一行会写明结果。判断错了，改 `<name>_layout.json` 顶层的 `"single"`，单栏时把每页的 `bands` 改成一个覆盖整页内容的跨栏带。

## 单栏论文的重排（render.py 的 flow 部分）

重排靠两件事：每一行文字属于哪一段（按文字匹配），以及没有文字的墨迹（图形、表格主体、公式）属于谁（按位置）。出问题时按现象找原因：

| 现象 | 原因与修法 |
|---|---|
| 图里的一条标签或一截图形跑到上一段的切片里 | 图中有一行文字恰好和上一段的文字重合。一行要有六成以上的 8 字符片段出现在段落原文里才算段落文字，窄行还要和上一行左端对齐；仍误判时，检查这一行在 `<name>_lines.json` 里的坐标 |
| 图被切成上下两块 | 图形内部的空隙超过 12 pt。`flow()` 里的 `GAP` 是“图形与图表题之间、图形内部”的最大空隙，个别论文可以调大 |
| 表格主体跑到下一张表或下一张图那里 | 图表题在图形上方还是下方是按全文多数情况自动判断的；同一篇论文里两种写法混用时会判错，需要手工调整 |
| 段落续行（图表后面接着排的半段）跑到图表块里 | 续行要和图表之前那一段的文字匹配上；段首带行内小标题（如“**Warehouse.** We build…”）的组按正文处理 |
| 切片顶部带着页眉线或“Preprint”字样 | 页眉页脚是“在三成以上页面重复出现的上下边缘文字”，其下方 6 pt 内的墨迹（页眉线）一并去掉。只出现在首页的页脚（如“Preprint submitted to Elsevier”）按页脚注处理 |
| 脚注夹在段落中间 | 页脚注的判定是：页面最底下、字号小于正文 93%、从左边起排的一串行。字号与正文相同的脚注识别不了，需要手工处理 |
| 段落之间有大段空白 | 切片之间按行间空白切成约 110 pt 一段，方便分页；一段里如果找不到空白行（比如整段是大公式），只能整块换页 |

## 双栏论文的段落拼接（render.py 的 do_col）

| 现象 | 原因与修法 |
|---|---|
| 左边只有半段原文、右边空着 | 续行没认出来。续行判断靠文字匹配（`continuation`），栏顶第一行离栏顶超过 15 pt、或续行文字和那一段的原文对不上（如 HTML 与 PDF 措辞不同）时会失败。段末是行间公式时，栏顶剩下的公式会直接拼回去 |
| 一段很长的原文拼完后挤到下一页、本页留大片空白 | 拼接后的行不能跨页断开。拼接上限是版心高度的 80%，需要时调小 `do_col` 里的 `0.8 * TEXTH` |
| 续行拼到了错误的段落后面 | 栏底是脚注时，暂存的是脚注上面那一段；其他情况暂存一栏的最后一组。若最后一组是浮动的图表，续行会认不出来，单独成一行 |
| 拼接处有一截空白 | 暂存的切片会把下沿收到最后一行墨迹，靠 `layout.swift` 的 `ink` 数据；旧版本生成的 `<name>_layout.json` 没有它，重跑 `layout.swift`（手工改过 `bands` 的页记得重新改） |

## PDF 模式（pdfblocks.py）

先把块框画到页面图上看，常见的错和修法（都写进 `<name>_blocks_override.json`，键是“页:y”或“页:y:x”，页从 0 数，y、x 取该行在 `<name>_lines.json` 里 y0、x0 的整数）：

| 现象 | 修法 |
|---|---|
| 小标题被并进了上一段或下一段 | `"heading": ["页:y"]` |
| 一段里的某一行被误判成小标题或公式 | `"para": ["页:y"]` |
| 一段被错误地切成两段 / 两段被并成一段 | `"join"` / `"split"` |
| 期刊首页的版权框、末页的期刊信息被当成正文 | `"meta_rect": [[页, x0, y0, x1, y1]]`，框内的行只裁切不翻译 |
| 某一行的文字框坐标明显不对（例如被根号撑到页面外） | `"setcol": {"页:y:x": ["L", x0, x1]}` |
| 图被当成正文、图里的标注混进段落 | 一般是图题没识别出来；图题要以 “Fig. N.” “Figure N” “Table N” 开头、字号比正文小 |

## 渲染与编译

| 现象 | 原因与修法 |
|---|---|
| `Undefined control sequence` 指向 `\par我们` | 中文字符紧跟在控制序列后面会被当成命令名的一部分。控制序列后面加空格或 `{}` |
| 中文里出现半角逗号、冒号、括号 | 渲染脚本会自动转换；仍残留的多半在 `**粗体**` 或公式旁边，直接在译文里写成全角 |
| pgfplots 报 `the input coordinate ... has not been defined with symbolic coords` | 符号坐标含英文括号要加花括号 `{Sim(3)}`；或相对坐标 `++(-22pt,0)` 里的 `0` 没带单位，改成 `([xshift=-22pt]axis cs:…)` |
| 参考文献每页只有一两条、页数暴增 | `multicols` 里不能用 `\offinterlineskip`，它会让 multicol 找不到分栏点 |
| `Overfull \vbox (1700pt too high)`，参考文献后面丢了几条、多出空白页 | 某一栏几乎是空的（比如最后一页只有左栏），很窄的切片被放大到栏宽后高度爆炸。`refstrips` 会跳过宽度小于 100 pt 或没有文字的栏 |
| 整页讲解的内容在页面上垂直居中 | preamble 里已把 `\@fptop` 设为 0；如果自己改了 preamble，保留这一行 |
| 图表里数字变成 `3·10^-2` 或 `1,248` | preamble 已全局关掉科学计数法和千位分隔；如果在单张图里覆盖了 number format，记得带上 `fixed` 和 `1000 sep={}` |
| 柱顶数字显示 0.03、0.1 | 误差类图表加 `ate labels` |
| 小节标题落在页底、图在下一页 | `\isec`、`\isub` 已自带“下面至少放得下几行”的检查；标题后紧跟一张图时还不够，在 `\isub` 前加 `\Needspace{16\baselineskip}`，节标题后紧跟小节再跟图时把 `\Needspace{20\baselineskip}` 放在 `\isec` 前 |
| `render.py` 报缺少译文 | 按列出的块号补齐 `<name>_zh.txt`；类型为 `[式 (n)]` 的块要写公式解释 |
| 分隔竖线跑到页面右侧 | 右栏译文为空时空盒子宽度为 0。preamble 的 `\bilrow` 已用 `\makebox[\colw]` 固定宽度，自己改 preamble 时保留 |
| 左右两栏的引用编号对不上 | HTML 版与 PDF 版参考文献排序不同。`render.py` 会按标题自动把译文改成 PDF 的编号，输出“引用编号按 PDF 改写”；如果提示“只对上 n/m 条，不改写”，说明参考文献表解析不可靠，需要人工核对 |

## 检查时容易漏的

- 解读改动章节顺序后，注释里“解读第 N 节”的引用没同步。
- 整页讲解超过一页：编译不报错，只在日志里留一条 `Float too large`，内容溢出到页外，必须看渲染图。
- 表格译文：原表格用颜色标最好/次好时，中文表只保留粗体和下划线；这是有意的简化，不用补颜色。
